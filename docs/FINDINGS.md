## 1. turn_on_init은 중요하지 않다 — 기울기 가설은 반증되었다

`softplus`의 도함수가 `sigmoid`이므로, 초기값 `v = -10`에서 꺼진 유전자를 켜는 항으로 가는
기울기가 `4.5e-5`배로 줄어든다. 첫 실행에서 `v_bias`가 60 에폭 동안 −10.000에서 −9.899로만
움직였고, **그 항이 죽은 구간에 초기화되었다고 판단했다.** 틀렸다.

combosciplex 검증 분할, 60 에폭, ridge 2.2305 대비:

| turn_on_init | softplus(v) | 기울기 | 모델 L2 | ridge 대비 |
|---|---|---|---|---|
| −10 | 0.000045 | 0.000045 | 2.1470 | **−0.0835** |
| −6 | 0.002476 | 0.002473 | 2.1640 | −0.0665 |
| −4 | 0.018150 | 0.017986 | 2.1450 | **−0.0855** |

기울기가 **400배** 차이 나는데 결과는 **0.002** 차이다. 잡음이다.

**진단값을 잘못 읽은 것이었다.** `to_v`의 가중치는 0에서 시작하므로 `v = 0·h + bias`이고,
학습은 전부 **가중치**에서 일어난다. bias만 보면 그 항이 죽어 보인다. 로그는 이제 가중치를
찍는다.

기본값은 −10으로 둔다. 셋 다 같은 성능이면 **학습 전 모델이 정확히 Control인 쪽**이 낫다 —
출발점이 이름을 가진다.

### 부수적으로 얻은 것: 전제 검사가 강해졌다

−6과 −4는 원래 전제 검사에 걸려 실행되지 않았다. "학습 전 모델은 Control"을 허용오차
1e-3으로 검사했는데, 편차가 **정확히 `softplus(v)`**이기 때문이다. 이제 그 값과 **같은지**를
검사한다 — 작은지가 아니라. 더 강한 검사이고, 그래서 이 쓸어보기가 가능해졌다.

## 2. 병목이 문제가 아니라 병목이 정규화였다 — 그리고 학습량이 진짜 지렛대다

첫 C1 측정이 갈렸다. norman additive fold 0에서는 ridge를 **−0.0518**로 넘고,
combosciplex에서는 **+0.0524**로 진다.

combosciplex는 조건이 7개뿐이고 교란 17개 중 13개가 단독 실험이 없다. 그래서
**표현력 부족**을 의심했다 — ridge는 교란마다 유전자 5,000개짜리 자유 벡터를 쓰는데, 이
모델은 전부 `embed_dim=64`와 공유 디코더를 지난다. 교란마다 유전자 공간 항을 하나씩
주었다 (`model.direct_gene_term`).

**반대였다.** combosciplex 검증, 250 에폭, ridge 2.2305 기준:

| | 학습 손실 | 테스트 L2 | ridge 대비 |
|---|---|---|---|
| 끔 | 0.769 | **1.6759** | **−0.5547** |
| 켬 | **0.371** | 2.4939 | +0.2634 |

**학습을 두 배 잘 맞히면서 테스트는 훨씬 못 맞힌다.** 교란 17개 × 유전자 5,000개 × 항 2개 =
자유 파라미터 170,000개를 **조건 19개**에 적합시킨 것이다. 과적합이다.

**없애려던 병목이 정규화였다.** 모델이 모자랐던 것은 표현력이 아니다.

### 모자랐던 것은 학습량이다

같은 설정, 같은 분할, 에폭만 다르게:

| 에폭 | 테스트 L2 | ridge 대비 |
|---|---|---|
| 60 | 2.1470 | −0.0835 |
| 250 | **1.6759** | **−0.5547** |

**학습량만으로 0.47이 움직인다.** 서버에서 처음 잰 400 에폭 결과(combosciplex +0.0524,
norman −0.0518)는 전부 심하게 덜 학습된 상태의 숫자이고, **그 숫자로 설계를 판단하면
안 된다.**

## 3. 학습 길이는 데이터셋마다 반대 방향이고, 고를 장치가 없었다

같은 코드, 같은 설정, 에폭만 다르게:

| | 400 에폭 | 2,500 에폭 |
|---|---|---|
| ComboSciPlex (fold 0, seed 0) | 1.9101 | **1.4900** |
| norman additive (fold 0) | **1.4955** | 1.7041 |

**정반대다.** 하나는 400에서 덜 학습되었고 하나는 2,500에서 과적합한다. 저 숫자들을 보고
데이터셋마다 에폭을 고르면 **테스트를 보고 고르는 것**이므로 할 수 없다.

### 시드 변동도 같은 원인이다

ComboSciPlex, 2,500 에폭, 시드만 다르게:

| 시드 | L2 |
|---|---|
| 0 | 1.4900 |
| 1 | 1.7964 |
| 2 | 1.7102 |
| **평균** | **1.6655** |

**폭이 0.31이다.** 그리고 평균 1.6655는 scDFM(1.6567)에 **진다.** 시드 0만 보고
"여섯 열 전부 최고"라고 적었던 것은 **운 좋은 시드 하나를 일반화한 것**이었고, 철회한다.

v2는 ridge 해에서 출발해 이 변동이 없었다 (시드 3개가 2.3305/2.4067/2.4032, 폭 0.08).
설계 문서 5.3절이 "출발점 보호를 포기한다"고 적어 둔 위험이 그대로 나타났다.

### 세 현상이 하나의 결함이다

**모델 선택이 없다.** 정해진 에폭만큼 돌리고 마지막 상태를 쓴다. 그래서 데이터셋마다
다른 지점에서 멈추고, 시드마다 최적 지점이 달라 변동이 커진다.

`scripts/epoch_curve.py`가 그 선택을 **검증 조건**에서 하게 한다. `train.save_every`로
에폭별 체크포인트를 남기고, 검증 분할 run 하나에서 곡선 전체를 읽는다. 테스트는 건드리지
않는다.

## 4. 1.4900은 운 좋은 추출이었다 — 그리고 EMA는 아무 일도 하지 않는다

ComboSciPlex 시드 0, 같은 설정, 세 가지 코드 상태:

| run | EMA | L2 |
|---|---|---|
| `c1_combo_long` (이전 코드) | 없음 | **1.4900** |
| `noema_combo_s0` (현재 코드) | 없음 | 1.8070 |
| `ema_combo_s0` (현재 코드) | 있음 | 1.8076 |
| `var_init_s0` (현재 코드) | 없음 | 1.8070 |

**EMA는 무죄다** — 1.8070과 1.8076은 같은 값이다. 코사인 스케줄이 이미 `1e-6`까지 감쇠하므로
마지막 구간에서 가중치가 거의 안 움직이고, 그 평균은 종점과 같다. **EMA를 켤 이유가 없다.**

차이를 만든 것은 `init_seed`를 넣으면서 `build_model` 뒤에 `torch.manual_seed`를 다시
호출하도록 바꾼 것이다. 난수 소비 순서가 달라져 **같은 `train.seed=0`이 다른 궤적**을 탄다.
버그가 아니라 다른 추출이고, 1.4900은 그중 운이 좋았던 하나다.

### 현재 코드에서의 실제 위치

| | L2 |
|---|---|
| ridge | 1.8577 |
| **scPKR2 (3시드 평균)** | **1.7713 ± 0.031** |
| scGPT | 1.6934 |
| CPA | 1.6592 |
| scDFM | 1.6567 |
| scPKR (v2) | 1.5836 |

**ridge만 이긴다.** scGPT, CPA, scDFM, v2에 전부 진다. v2까지 **+0.188**, scDFM까지
**+0.115**이고, 3시드 표준오차가 0.031이므로 **이 격차는 잡음이 아니다.**

### 철회

`scripts/paper_compare.py`의 Table 3에 채운 `scPKR2` 행은 전부 `c1_combo_long`에서 나온
것이다 — L2도, cell-eval 다섯 열도. **그 run은 운 좋은 추출이자 지금은 없는 코드 상태의
것이므로 그 행 전체를 철회한다.** "여섯 열 전부 최고"라고 두 번 적었고 두 번 다 같은 하나의
run에 기대고 있었다.

## 5. C1 판정 — 학습된 가법 성분은 닫힌 형태를 넘지 못한다

설계 문서가 미리 적어 둔 조건이다.

> **C1.** 1단계가 무작위 초기화로 ridge를 넘지 못하면, "학습된 가법 성분" 가설은 반증된다.

학습 길이는 **검증 조건**에서 골랐다 (norman 500, 각 길이가 자기 스케줄을 끝까지 돈 독립
run 다섯 개를 비교). 테스트는 보지 않았다.

### norman additive, fold 0, 500 에폭, 시드 3개

| | L2 |
|---|---|
| ridge | 1.5473 |
| **scPKR2** | **1.5630 ± 0.024** |
| scPKR (v2) | 1.4532 |

ridge와의 격차 **+0.016**은 표준오차의 0.6배이므로 **구분되지 않는다** — 비긴다. v2와의
격차 **+0.110**은 표준오차의 **4.5배**이므로 분명히 진다.

### combosciplex, 시드 3개

| | L2 |
|---|---|
| ridge | 1.8577 |
| **scPKR2** | **1.7713 ± 0.031** |
| scDFM | 1.6567 |
| scPKR (v2) | 1.5836 |

ridge는 넘지만 발표된 모델 전부와 v2에 진다.

### 판정

**두 데이터셋 모두에서, 검증으로 고른 길이와 시드 평균으로, ridge를 넘지 못한다.**
combosciplex에서 조금 넘는 것은 그 블록에서 ridge 자체가 약하기 때문이고(1.8577로 발표
모델 전부보다 나쁘다), 넘어도 다른 누구도 이기지 못한다.

**C1이 반증되었다.** "작은 데이터라 불리했다"는 설명도 성립하지 않는다 — norman은 조건이
훨씬 많고 거기서도 비긴다.

이것은 scDFM(1.7043)과 CellFlow(1.7064)가 ridge(1.6690)에 진 것과 같은 현상이며, 이제
**같은 구조를 세포 조건부·비음수로 다시 지어도 반복된다**는 것까지 확인되었다. 이 과제에서
**가법 구조는 경사하강으로 안정적으로 복원되지 않는다.**

### 남은 것은 설계 문서가 정해 둔 길이다

> C1에 걸리면 ridge 초기화를 붙여 차이를 재고, **그 의존을 결과로 보고한다. 숨기지 않는다.**

다만 이 파라미터화에서 ridge 해를 그대로 초기값으로 쓸 수 없다. `mu = x exp(u) + softplus(v)`
는 `x + w`를 표현하지 못한다 — `w < 0`인 자리에서 `exp(u) = 1 + w/x`가 되어 세포마다 달라지기
때문이고, **그 표현 불가능성이 음수를 못 내는 이유 자체**다. 곱셈 쪽의 대응물은 덧셈 가중치가
아니라 **로그 배수비**이며, 그것을 ridge로 적합해 `u`의 초기값으로 쓰는 것이 이 구조에 맞는
형태다.

## 6. fold 난이도 — 개발은 fold 3에서 한다

ridge, norman additive, fold별 (학습 없이 닫힌 형태로 계산):

| fold | ridge L2 |
|---|---|
| 0 | 1.5473 |
| 1 | 1.5379 |
| 2 | 1.7329 |
| **3** | **1.8592** |
| 4 | 1.6699 |
| 평균 | 1.6695 |

평균 1.6695가 기록된 1.6690과 맞으므로 **단위가 검증되었다.**

**가장 쉬운 fold와 가장 어려운 fold가 0.32 벌어진다.** 그리고 이 세션의 모든 설계 판단은
fold 0 — **두 번째로 쉬운 fold** — 에서 내려졌다. fold 0의 숫자를 발표 표의 5 fold 평균과
나란히 놓은 것은 비교가 아니다.

### 규칙

| | |
|---|---|
| 개발 | **fold 3만**, 시드 3개. 가장 어려우므로 개선이 보수적이다 |
| 최종 보고 | **5 fold 전부**, 시드 3개. 논문 숫자는 이것뿐이다 |

**개발 fold의 숫자는 발표 표와 비교하지 않는다.** 단서를 달아도 결론은 혼자 걸어다닌다.

## 7. fold 3 — 5절의 C1 판정은 성급했고, ridge 초기화는 효과가 없다

norman additive **fold 3** (가장 어려운 fold), 500 에폭, 시드 3개, soft, 4,096 cells:

| | 시드 0 | 시드 1 | 시드 2 | 평균 | 표준편차 |
|---|---|---|---|---|---|
| ridge | | | | 1.8592 | — |
| scPKR2, 무작위 초기화 | 1.7077 | 1.7490 | 1.7510 | **1.7359** | 0.024 |
| scPKR2, ridge 초기화 | 1.7076 | 1.7482 | 1.8034 | 1.7531 | 0.048 |
| scPKR (v2) | 1.7190 | 1.7265 | 1.7222 | **1.7226** | 0.004 |

### 5절을 정정한다

5절은 "두 데이터셋 모두에서 ridge를 넘지 못한다, C1이 반증되었다"고 적었다. **norman에
대해서는 fold 0 하나를 보고 한 말이었다.** fold 3에서는 무작위 초기화 그대로 ridge를
**−0.123, 표준오차의 8.7배**로 넘는다.

| fold | ridge | scPKR2 (무작위) | 차이 |
|---|---|---|---|
| 0 | 1.5473 | 1.5630 | +0.016 (비김) |
| 3 | 1.8592 | 1.7359 | **−0.123** |

**C1은 5 fold 평균으로만 판정할 수 있고, 아직 판정되지 않았다.** 쉬운 fold에서는 ridge가
이미 거의 다 맞혀서 남는 것이 없고, 어려운 fold에서 학습이 값어치를 낸다.

### ridge 초기화는 채택하지 않는다

무작위 초기화 1.7359, ridge 초기화 1.7531. 차이 +0.017은 표준오차의 0.6배이고 방향도
나쁜 쪽이다. **효과가 없다.** 모델에 ridge를 들일 근거가 없으므로 들이지 않는다 —
`model.init_from_ridge`와 `model.direct_gene_term`은 기본값(꺼짐) 그대로 둔다.

시드 0과 1의 값이 두 설정에서 소수점 셋째 자리까지 같다(1.7077/1.7076, 1.7490/1.7482).
직접 항과 그 초기값이 최종 예측에 거의 기여하지 않는다는 뜻으로 읽히지만 **확인하지는
않았다.**

### v2와는 가장 어려운 fold에서 비긴다 — 그러나 6배 덜 안정적이다

scPKR2 1.7359 대 v2 1.7226, 차이 +0.013은 표준오차의 0.9배. **구분되지 않는다.**
fold 0에서는 0.11 졌다. 그리고 시드 표준편차가 0.024 대 0.004로 **v2가 6배 안정적**이다 —
ridge에서 출발하는 것의 이점이 평균이 아니라 분산에 남아 있다.

## 9. norman에서는 단일도 조합도 제 몫을 한다

`scripts/decompose_gap.py`, norman additive 5 fold (시드 0), 테스트 double 37개씩.
전부 실제 double 평균에 대한 L2.

## 12. 보고 규약 — L2는 soft, 나머지 다섯 열은 sample

2026-10-13에 확정. scPKR(v2)의 최종 표가 쓰던 조합과 같다.

| 열 | 게이트 | 무엇을 재는가 |
|---|---|---|
| L2 | **soft** | 모델이 내놓는 평균 `q × m` 그 자체 |
| MSE, MAE, DE-Spearman, Pearson Δ, DS | **sample** | 그 평균에서 뽑은 세포 (`Bernoulli(q) ×` 베타 추출) |

둘 다 세포 평균 한계(`--bound-mean`) 아래에서 잰다. 한 명령으로 나온다:

    python scripts/paper_table.py <runs> --gate sample --l2-gate soft --bound-mean ...

**이 모델에서는 규약이 열을 움직이지 않는다.** norman additive에서 soft L2는 1.6439,
sample L2는 1.6460으로 0.002 차이다. v2에서는 이 차이가 0.09~0.70이어서 규약이 결과를
좌우했다.

Table 1, 이 규약으로:

| | L2 | MSE | MAE | DE-Spearman | Pearson Δ | DS |
|---|---|---|---|---|---|---|
| scDFM | 1.7043 | 0.00315 | 0.02155 | 0.5705 | 0.8853 | 0.9737 |
| CellFlow | 1.7064 | 0.00392 | 0.02207 | 0.5503 | 0.8678 | 0.9321 |
| **scPKR2** | **1.6439** | 0.00386 | 0.02281 | 0.4200 | 0.8805 | 0.9639 |

hard 게이트는 v1, v2, 이 저장소 어디에서도 보고에 쓰인 적이 없다.

## 13. 게이트 세 가지 — soft가 거의 모든 열에서 가장 좋다 (기준선 확인 전)

norman additive, 5 fold × 시드 3개, 세포 평균 한계. 같은 체크포인트를 게이트만 바꿔 export하고
cell-eval 0.8.1로 채점했다.

| | L2 ↓ | MSE ↓ | MAE ↓ | DE-Spearman ↑ | Pearson Δ ↑ | DS ↑ |
|---|---|---|---|---|---|---|
| scDFM | 1.7043 | **0.00315** | 0.02155 | 0.5705 | 0.8853 | **0.9737** |
| CellFlow | 1.7064 | 0.00392 | 0.02207 | 0.5503 | 0.8678 | 0.9321 |
| Additive | 1.9395 | 0.00448 | 0.02276 | 0.5564 | **0.9024** | 0.9686 |
| scPKR2, hard | 2.3686 | 0.00627 | 0.03512 | −0.1199 | 0.8018 | 0.9629 |
| scPKR2, sample | 1.6460 | 0.00386 | 0.02281 | 0.4200 | 0.8805 | 0.9639 |
| **scPKR2, soft** | **1.6439** | 0.00345 | **0.02045** | **0.8330** | 0.8986 | 0.9629 |

**hard는 쓸 수 없다.** 평균을 보존하지 않아 L2가 2.37이 되고 DE-Spearman은 음수다.

**soft는 sample보다 다섯 열에서 낫고 DS만 같다.** scDFM과는 L2, MAE, DE-Spearman,
Pearson Δ 네 열을 이기고 MSE와 DS 두 열을 진다.

### 왜 soft가 나은가

이 모델의 출력 `mu = x exp(u) + softplus(v)`는 평균 벡터가 아니라 **대조군 세포 하나를
변조한 것**이다. 곱셈 항은 그 세포의 0을 0으로 두고 켜진 값만 조절하므로, soft 출력은 실제
세포의 구조를 물려받는다 — flow 기반 모델이 대조군 세포를 결정론적으로 옮기는 것과 같은
종류의 예측이다. sample은 그 구조를 버리고 `Bernoulli(q) ×` 베타에서 새로 뽑는다. 평균은
같지만 세포 수준의 모양에 잡음이 들어가고, 차등발현 통계가 그것을 본다.

v2에서 sample이 필요했던 이유는 soft 출력에 음수가 있어 cell-eval이 거부했기 때문이다.
여기서는 그 이유가 없다.

### 아직 믿으면 안 되는 이유

**DE-Spearman 0.83은 발표된 어떤 모델보다 0.26 높다.** 그만큼 큰 차이는 모델이 좋아서일
수도, **채점 방식이 발표 표와 달라서**일 수도 있다. L2에 대해서는 Control과 Additive를
같은 파이프라인으로 재현해 척도를 확인했지만(3 % 이내), 나머지 다섯 열에 대해서는 그 확인을
한 적이 없다.

`run_celleval.py --baseline control|additive`가 그 확인을 한다. 대조군 세포 그대로, 그리고
실제 단일 효과를 더한 세포를 **같은 export와 같은 채점기**에 넣는다. 그 결과가 발표 표의
Control 행(MSE 0.01839, MAE 0.03953, DS 0.5135)과 Additive 행(MSE 0.00448, MAE 0.02276,
DE-Spearman 0.5564, Pearson Δ 0.9024, DS 0.9686)을 재현하면 채점기가 같은 것이고, soft의
숫자를 발표 표와 나란히 놓을 수 있다. **재현하지 못하면 이 표의 다섯 열은 비교가 아니다.**

## 14. 기준선 재현 — 네 열은 같은 척도, DE-Spearman은 아니다

발표 표의 Control과 Additive 행을 이 저장소의 export와 채점기(cell-eval 0.8.1)로 다시
만들었다. norman additive 5 fold, 테스트 double.

| 기준선 | 열 | 발표 값 | 재현 값 | 비율 |
|---|---|---|---|---|
| Control | MSE | 0.01839 | 0.01886 | 1.026 |
| Control | MAE | 0.03953 | 0.04268 | 1.080 |
| Control | DS | 0.5135 | 0.5145 | 1.002 |
| Additive | MSE | 0.00448 | 0.00422 | 0.942 |
| Additive | MAE | 0.02276 | 0.02316 | 1.018 |
| Additive | Pearson Δ | 0.9024 | 0.9061 | 1.004 |
| Additive | DS | 0.9686 | 0.9752 | 1.007 |
| Additive | **DE-Spearman** | **0.5564** | **0.6286** | **1.130** |

**MSE, MAE, Pearson Δ, DS는 재현된다** — 0.2~8 % 안이다. 이 네 열은 발표 표와 나란히 놓을 수
있다.

**DE-Spearman은 재현되지 않는다.** 같은 Additive 기준선이 발표 표에서는 0.5564, 이
채점기에서는 0.6286이다. 이 채점기가 0.07 높게 읽는다. cell-eval의 버전이나 DE 검정 설정이
논문과 다른 것으로 보이며, 논문은 버전을 밝히지 않는다.

### 그래서 DE-Spearman에 대해 말할 수 있는 것

| | DE-Spearman | Additive 대비 |
|---|---|---|
| 발표 표: Additive | 0.5564 | — |
| 발표 표: scDFM (최고) | 0.5705 | +0.014 |
| 이 채점기: Additive | 0.6286 | — |
| 이 채점기: scPKR2 soft | 0.8330 | **+0.204** |
| 이 채점기: scPKR2 sample | 0.4200 | −0.209 |

**scPKR2 soft의 0.8330을 발표 표의 0.5705 옆에 그대로 놓으면 안 된다.** 말할 수 있는 것은:
같은 채점기에서 Additive 기준선보다 0.204 높고, 발표 표에서는 어떤 모델도 자기 Additive를
0.014 넘게 앞서지 못한다는 것이다. 강한 증거이지만 같은 척도의 숫자는 아니다. 같은 척도로
만들려면 scDFM과 CellFlow를 공개 코드로 같은 fold에서 돌려 이 채점기로 채점해야 한다.

### 재현된 네 열에서 scPKR2 soft의 위치

| | scPKR2 soft | scDFM | 판정 |
|---|---|---|---|
| L2 | 1.6439 | 1.7043 | 이김 (ridge로 척도 확인) |
| MAE | 0.02045 | 0.02155 | 이김. 채점기는 기준선 MAE를 2~8 % **높게** 읽으므로 유리한 쪽의 오차가 아니다 |
| Pearson Δ | 0.8986 | 0.8853 | 이김, 근소. 채점기 오차 +0.004를 빼도 +0.009 |
| MSE | 0.00345 | 0.00315 | 짐 |
| DS | 0.9629 | 0.9737 | 짐 |

## 15. 보고 규약 변경, 그리고 발표 표의 채점 프로토콜

### 규약: 여섯 열 전부 soft

2026-10-13에 12절의 규약("L2는 soft, 나머지는 sample")을 **"여섯 열 전부 soft"**로 바꾼다.
13절의 측정이 근거다 — soft가 sample보다 다섯 열에서 낫고, 하나의 예측에서 전부 나온다.

    python scripts/run_celleval.py <run> --gate soft --bound-mean ...

### scDFM이 실제로 채점한 방식

14절에서 DE-Spearman이 발표 값과 어긋났다 (Additive 기준선 0.6286 대 0.5564). scDFM의 공개

| | scDFM (`src/script/run.py`의 `test()`, `environment.yml`) | 이 저장소 (지금까지) |
|---|---|---|
| cell-eval | **0.5.42**, pdex 0.1.21 | 0.8.1 |
| 섭동당 예측 세포 | **128개** (`N = 128; source = source[idx][:N]`) | 실제 세포 수와 동일 |
| 실제 세포 | 전부 | 전부 |
| 호출 | `MetricsEvaluator(pred, real, control_pert, pert_col, num_threads=32).compute()` | 같음 |

예측 세포가 128개뿐이면 fold change 추정에 잡음이 커져 DE-Spearman이 낮아진다. Additive

재현하는지가 다음 확인이다.** 재현되면 그것이 발표 표와 같은 척도이고, 다섯 열을 전부 그
방식으로 다시 잰다.

## 16. DE-Spearman은 `de_spearman_sig`였다 — 다른 열을 읽고 있었다

Additive 기준선, 섭동당 예측 세포 128개, norman additive 5 fold:

| | `de_spearman_sig` | `de_spearman_lfc_sig` | MSE | MAE | Pearson Δ | DS |
|---|---|---|---|---|---|---|
| cell-eval 0.8.1 | **0.5550** | 0.6114 | 0.00429 | 0.02360 | 0.9019 | 0.9733 |
| cell-eval 0.5.42 (pdex 0.1.21) | **0.5543** | 0.6557 | 0.00429 | 0.02360 | 0.9019 | 0.9560 |
| 발표 표의 Additive | **0.5564** | | 0.00448 | 0.02276 | 0.9024 | 0.9686 |

**발표 표의 "DE-Spearman ρ"는 `de_spearman_sig`다.** 두 채점기 모두 0.4 % 안에서 재현한다.
`paper_table.py`는 v2 때부터 이름이 비슷한 `de_spearman_lfc_sig`를 읽어 왔다.

| | 무엇을 재는가 |
|---|---|
| `de_spearman_sig` | 섭동별 **유의한 DE 유전자 개수**의 순위 상관. 채점 파일 하나에 숫자 하나 |
| `de_spearman_lfc_sig` | 유의한 유전자들의 **fold change** 순위 상관. 섭동마다 하나 |

발표 표 자체에 단서가 있었다. STATE는 Pearson Δ가 −0.0108인데 DE-Spearman이 0.5288이고,
Control은 N.A.다 — fold change 상관으로는 나올 수 없고, 개수가 전부 0인 상관으로는 나온다.

**따라서 이 문서의 11~14절에 적힌 DE-Spearman 값(0.42, 0.83, 0.6286 등)은 전부 발표 표에
없는 지표의 값이다.** 발표 표와의 비교에 쓸 수 없다. 나머지 네 열의 결론은 영향받지 않는다.

### 나머지 확인된 것

- cell-eval 0.5.42가 죽던 이유는 **pdex 버전**이었다. scDFM이 고정한 0.1.21에서는 돈다.
  0.1.28에서는 두 군에서 동점인 유전자가 NaN p-value를 내고 FDR 보정이 그것을 거부한다.
- 예측 세포를 128개로 맞추면 Pearson Δ가 0.9061 → 0.9019로 발표 값 0.9024에 붙는다.
- DS만 버전에 따라 다르다 (0.9733 대 0.9560, 발표 값 0.9686은 그 사이).

### 이 지표의 성질이 요구하는 것

`de_spearman_sig`와 DS는 **채점 파일 안의 모든 섭동에 걸쳐** 계산된다. 행을 걸러서는 나눌 수
없으므로, Single과 Double을 따로 보고하는 Table 2는 **블록별로 따로 export해 따로 채점**해야
한다 (`run_celleval.py --group single|double`, `paper_table.py --group-export`).

### 확정된 프로토콜

발표 표와 나란히 놓는 숫자는 다음으로 잰다: soft 게이트, 세포 평균 한계, **섭동당 예측 세포
128개**, **cell-eval 0.5.42 + pdex 0.1.21** (`requirements-celleval-scdfm.txt`),
DE-Spearman은 `de_spearman_sig`.

## 21. 비교 실험 — 지수 사상과 공유 모드는 값어치를 내고, 관측 공간 손실과 KEGG는 내지 못한다

norman additive **fold 3**, 250 에폭, 시드 3개, soft, 세포 평균 한계, 4,096 cells,
테스트 double 37개. `scripts/stage2_arms.sh`. ridge가 1.8592로 나와 설정이 맞았음을 확인했다.

| 실험 | 바꾼 것 | 시드 0 / 1 / 2 | 평균 | 표준편차 | B 대비 | 판정 |
|---|---|---|---|---|---|---|
| B | 생성자 모델 | 1.6979 / 1.6763 / 1.6769 | **1.6837** | 0.0123 | — | **S1 통과** |
| C | 지수 제거 (`dp = B p`) | 2.0836 / 2.0475 / 2.0399 | 2.0570 | 0.0233 | **+0.373** | **S2 통과** |
| D | 관측 공간 손실 제거 | 1.6873 / 1.6859 / 1.6825 | 1.6852 | 0.0025 | +0.002 | **S3 불통과** |

기준: ridge 1.8592, 1단계 MLP 1.7519 (19절).

**B.** 검증이 고른 250 에폭에서 1.6837 — 500 에폭의 1.7118(19절)보다 낫다. 검증 분할의
선택이 테스트 fold에서도 맞았다. ridge보다 0.176, MLP보다 0.068 낫다.

**C — 지수 사상이 이 모델의 핵심이다.** 지수를 빼면 ridge보다도 0.198 나빠진다. C는 이동이
더해지는 모델(`dp_S = dp_a + dp_b`)이므로 `u_S = u_a + u_b`, 곧 **곱셈 귀무모형** 그 자체다
(설계 2.3 정정 참고). 곱셈 귀무모형은 log1p 공간에서 가법인 ridge에게 지고, 지수 사상의
고차 항이 그것을 0.373 되돌려 ridge를 넘긴다. **고차 항이 무엇을 하는지** — 시너지인지,
곱셈 귀무모형의 과잉 누적을 깎는 포화 보정인지 — 는 이 표로 알 수 없다.

**D — 사전 규칙대로 관측 공간의 두 손실을 뺀다.** 차이 +0.0015는 문턱 0.01 안이다. 설계
4절에 적은 대로 연산자 경로를 "관측량 위의 동역학"이라 부르지 않으며, Koopman이라는 이름도
내용을 잃는다. D는 시드 표준편차도 가장 작다(0.0025). **이후 run은 D의 설정으로 한다**
(`scripts/stage2_folds.sh`).

**E — 경로 사전지식이 기여한다고 쓸 수 없다.** 무작위 묶음이 오히려 0.003 낫고 시드 잡음
안이다. E는 경로 행 211개만 무작위로 바꾸고 **앵커 256개(표적 포함)는 그대로 둔다.** 반박된
것은 "어떤 유전자들이 한 좌표로 묶이는가가 중요하다"는 주장이다. KEGG 좌표는 해석을 위해
유지하고 이 대조를 함께 보고한다.

norman fold 3의 실제 크기: 유전자 G = 5,030, 경로 211 + 앵커 256 = K 467, 상수 포함 468차원.
경로나 앵커가 닿는 유전자는 2,400개이고 **2,630개(52 %)는 어느 좌표에도 속하지 않는다.**

**F.** `kappa`를 따로 두면 나빠지고 불안정하다(시드 1에서 1.7677). 지수 사상이 주는 상호작용
이상은 필요 없다.

**G — 설계 2.4의 전제가 틀렸다.** 표준화는 처리군을 포함한 학습 세포 전부로 맞추므로
(`training_rows`) 대조군 세포가 `Phi = 0`에 있지 않고, 상수 없이도 평균 효과를 실을 수 있다.
상수 좌표는 남기되 정확도에 대한 주장은 하지 않는다.

**H.** 교란별 자유 저계수만으로는 ridge보다 0.083 나쁘다. 공유 모드가 없으면 과적합한다.

### 남는 주장

- 교란 = 공유 모드 위의 저계수 생성자, 조합 = 생성자의 합의 지수. 상호작용 전용 파라미터 없이
  곱셈 귀무모형(C)보다 0.373, ridge보다 0.176 낫다.
- 공유 모드가 없으면 성립하지 않는다(H).

### 철회하는 주장

- 관측 공간 손실이 값어치를 낸다 (S3).
- KEGG 경로 묶음이 기여한다 (S4).
- 상수 좌표가 있어야 평균 효과를 표현할 수 있다 (G).

다음: 5 fold × 시드 3개, D 설정 (설계 8절 5번, S6). fold 3은 `s2D_s0..2`가 같은 설정이다.

## 24. 부드러운 사전 (KEGG 뼈대 + 벌점 잔차) — H2 불통과, 그러나 구조와 무관한 정확도 향상

`docs/DESIGN_PRIOR.md`. λ = 0.001 (H0, 검증 분할). 판정 fold 0, 1, 2, 4 × 시드 3개, 250 에폭,
D 설정, 백색화 없음, 뼈대 = KEGG 지도 링크.

### H2 (1차, 생물학): 불통과

그래프 밖 비율 — KEGG 뼈대 평균 0.8556, 섞은 뼈대 0.8476. **12쌍 중 KEGG가 낮은 것은 2쌍**
(부호 검정 p = 0.997). 기준은 10쌍이었다. 사전 규칙대로 **KEGG를 생성자 구조에 넣는 방향은 닫는다.**

λ = 0.001에서 생성자 에너지의 약 87 %가 잔차 가지에 있다. 뼈대가 KEGG든 섞은 것이든 상관 그래프든
비율이 0.85 근처로 같다.

### L2 (판정 fold 4개)

| | fold 0 | fold 1 | fold 2 | fold 4 | 평균 |
|---|---|---|---|---|---|
| ridge | 1.5473 | 1.5379 | 1.7329 | 1.6699 | 1.6220 |
| 1단계 MLP (8절) | 1.5630 | 1.5196 | 1.6498 | 1.7256 | 1.6145 |
| D (조밀 생성자, `s2fin`) | 1.4739 | 1.4791 | 1.6193 | 1.5442 | 1.5291 |
| **KH** (KEGG 뼈대 + 잔차) | 1.4210 | 1.5137 | 1.5064 | 1.4766 | **1.4794** |
| PH (섞은 뼈대 + 잔차) | 1.4211 | 1.4956 | 1.4928 | 1.4810 | 1.4726 |
| RH (상관 뼈대 + 잔차, 시드 0) | 1.4010 | 1.4625 | 1.4973 | 1.4869 | 1.4619 |

- **H1 통과:** KH − D = −0.050 (12쌍 중 9쌍에서 KH가 낫다).
- **H2':** PH − KH = −0.007 ± 0.030, KEGG가 나은 쌍 5/12. KEGG 뼈대는 정확도도 높이지 않는다.
- **H3:** RH가 셋 중 가장 낮다(시드 하나).

### 예상하지 못한 것: 뼈대와 무관한 향상

**뼈대 + 잔차 구조 자체가 D보다 약 0.05~0.07 낫다** — 뼈대가 KEGG든(−0.050), 섞은 그래프든
(−0.057, 10/12쌍), 상관 그래프든. 생물학이 아니라 구조의 효과다. 원인은 아직 모른다. 후보:

- 생성자 용량이 두 배 (가지 두 개, 0.41 M → 0.82 M)
- 벌점 없는 성긴 가지 + 벌점 있는 조밀 가지라는 분해 (성긴 + 저계수 분해와 비슷하다)
- 잔차를 0에서 시작하는 초기화 (모델이 성긴 생성자로 출발)
- 백색화 없음 — fold 3에서는 백색화를 끄면 오히려 나빴다(D0, 22절)이므로 가능성은 낮다

이것은 **사후 관찰**이다. 미리 세운 가설(H1)은 "D보다 0.02 넘게 나쁘지 않다"였고, "낫다"는 주장은
원인을 가리는 ablation과 판정에 쓰지 않은 데이터(Table 2·3)에서의 확인이 있어야 쓸 수 있다.

### KEGG 밖 결합 후보 (12/12 run 공통)

상위 20개 중 16개가 **Ribosome 경로로 들어가는 결합**이다(FOXF1, CEBPE, PRTG, HOXA13, TBX3, HBA1 등
여러 표적 앵커에서). 많은 교란이 공통으로 리보솜·번역 프로그램을 움직인다는 뜻으로 읽히며, 세포
성장 상태의 일반적 반응일 가능성이 높다. 새 생물학적 상호작용이라기보다 데이터의 공통 축이다.
검증되지 않은 후보로만 다룬다.
